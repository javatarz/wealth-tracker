# Research: FOSS parser for CAMS CAS PDFs — which one, and what it reliably extracts

**Verification date: 2026-09-19 (Asia/Kolkata).** Licence, release-date, maintenance and CVE statements below are point-in-time and must be re-checked before the spec is frozen (several candidates ship multiple releases per month).

**Scope of criteria applied:** Python ecosystem; licence that permits non-commercial use; actively maintained and/or mature; no known unpatched CVEs; no transmission of statement contents to a third party.

---

## Summary

Use **[casparser](https://github.com/codereverser/casparser)** (PyPI `casparser`, MIT, v1.4.1 released 2026-08-30). It is the only candidate with a serious maintenance record (2020→2026, 228 stars, ~monthly releases since June 2026), a full per-folio / per-scheme / per-transaction model, an explicit local-only parse path, and machine-readable JSON Schemas checked into the repo. It extracts scheme name, ISIN, folio, NAV, units, cost (holding level), transaction date and a typed transaction type, and it handles multi-page statements (v1.1.0's region-based header parser stitches scheme headers across page breaks).

Two hard boundaries must go into the spec as **first-class error paths, not afterthoughts**: casparser parses only *original, issuer-delivered* CAS PDFs (re-prints, browser "Save as PDF", broker-reformatted files and MFCentral statements are explicitly rejected), and it targets the **consolidated** CAS variants (CAMS "Detailed"/"Summary" and KFintech "Detailed"/"Summary") — **single-AMC statements are outside its documented scope** and are expected to fail issuer detection.

The strongest fallback is **[cas2json](https://github.com/BeyondIRR/cas2json)** (CC0-in-spirit AGPL-3.0, v1.2.7 released 2026-08-21) — it parses CAMS/KFintech and (holdings-only) NSDL/CDSL, but its PDF engine is PyMuPDF (AGPL-3.0-or-later unless a commercial licence is bought), the repo currently has **no test suite**, and NSDL/CDSL accuracy is self-declared BETA.

## Finding 0 (naming): three different documents get called "the CAMS statement"

This distinction drives parser selection, so it is stated first.

| Document | Issuer / source | Covers | Called by |
|---|---|---|---|
| **Consolidated Account Statement (CAS) — RTA variant** | Generated by the RTA; CAMS variant requested at `mailback.camsonline.com`; KFintech variant requested at `mfs.kfintech.com` | Every folio whose RTA is that registrar — so **one CAS PDF can mix several AMCs**, and (per casparser's per-scheme `rta` field) a CAMS-issued CAS can carry KFin-serviced schemes | "CAMS CAS", "KFintech CAS" |
| **Consolidated CAS across both RTAs (+ demat)** | Joint CAMS + KFintech mailback service | All AMC folios linked to the investor's PAN, plus demat holdings when generated via NSDL/CDSL | "CAS", "full CAS" |
| **Single-AMC statement of account / transaction statement** | A single AMC (often produced by its RTA) or an AMC portal download | Only that fund house | Also colloquially "CAMS statement" |

Evidence for the joint CAMS+KFin mailback and its scope: *"KFintech and CAMS have come together to provide great convenience to investors by allowing them to see a consolidated view of their portfolio as a Mailback Statement."* — [KFintech CAS page](https://mfs.kfintech.com/investor/General/ConsolidatedAccountStatement). For the CAMS-side entry point and the two statement variants, see [CAMS — Consolidated Account Statement](https://www.camsonline.com/Investors/Statements/Consolidated-Account-Statement) (page is JavaScript-rendered; the server-side HTML could not be read, so the CAMS wording below is cited from casparser's own README table rather than from CAMS directly — flagged as a **missing-evidence** item).

## Recommendation (detail)

**Primary: `casparser` >= 1.4.1, pinned, MIT, local-only.**

Reasons, each with its own source, are in the candidate section below. Short form:

1. **Licence clean end-to-end.** PyPI metadata: `license_expression: "MIT"`; v1.0 removed the PyMuPDF/GPL extras and rewrote the PDF layer on pypdfium2 (Apache-2.0 / BSD-3), so there is no transitive copyleft — [PyPI JSON](https://pypi.org/pypi/casparser/json), [v1.0.0 release notes](https://github.com/codereverser/casparser/releases/tag/v1.0.0).
2. **No statement data leaves the machine.** Dependencies are `casparser-isin`, `click`, `colorama`, `pydantic`, `pypdfium2`, `python-dateutil`, `rich` — no HTTP client, so the parse path cannot call out — [PyPI JSON](https://pypi.org/pypi/casparser/json). The only network-touching code found anywhere in the family is the *separate* `casparser-isin --update/--check` CLI ([source](https://github.com/codereverser/casparser-isin/blob/main/casparser_isin/cli.py)), which pulls an ISIN database from `https://casparser.atomcoder.com/` — and even that sends no statement content (see Privacy section).
3. **Field coverage matches the spec, with one exception** (per-transaction cost basis — see Gaps).
4. **Maintenance is real, not nominal.** Latest release 1.4.1 on 2026-08-30, last commit 2026-08-28, releases roughly monthly since 1.0.0 (2026-06-08) — [PyPI JSON](https://pypi.org/pypi/casparser/json), [repo metadata](https://api.github.com/repos/codereverser/casparser).
5. **Safety net for silent mis-parses.** `CASData.parse_warnings` reconciles each scheme's transactions against the statement's own printed running unit balance and emits a non-fatal warning on discontinuity — [v1.1.0 release notes](https://github.com/codereverser/casparser/releases/tag/v1.1.0), [README](https://github.com/codereverser/casparser).

**Fallback: `cas2json`, only if casparser fails on a real user statement and only if AGPL is acceptable.** Trade-offs in its section.

**Do not use:** `processcaspdf` (tiny, regex-on-text, HTTP fetch on every run), `mutualfund-stmts-etl` (dead since 2019, needs Java/Tabula), `saransh-workflows` (v0.1.0, one release, unproven), `CAMSPdfExtractor` (dead since 2023), and anything in the `cas-parser-python` / `casparser.in` family (they are clients for a **hosted** API that receives the PDF — fails the no-third-party criterion outright).

**What it handles (explicit):** *original* CAS PDFs from four issuers — CAMS (Detailed, Summary, via `mailback.camsonline.com`), KFintech (Detailed, Summary, via `mfs.kfintech.com`), NSDL (demat consolidated), CDSL (demat consolidated) — [README "Supported inputs"](https://github.com/codereverser/casparser). One CAS PDF may mix registrars; the model carries both `file_type` (CAMS/KFINTECH = issuer) and a per-scheme `rta` (`"CAMS"`, `"KFINTECH"`, …) — [README data structure](https://github.com/codereverser/casparser), [CASData schema](https://github.com/codereverser/casparser/blob/main/schema/CASData.schema.json).

**Per-holding / per-transaction coverage against the functional requirements** (source: [README `CASData` shape](https://github.com/codereverser/casparser); `docs/research` readers should treat this as *direct evidence* since the fields are printed in the README and generated into `schema/CASData.schema.json`):

| Requirement | Field | Notes |
|---|---|---|
| Scheme name | `folios[].schemes[].scheme` | ✅ |
| ISIN | `schemes[].isin` | ✅ but `string \| null` — see Gaps |
| Folio number | `folios[].folio` (e.g. `"12345678 / 90"`) + `amc` | ✅ |
| NAV | `schemes[].valuation.nav`, `transactions[].nav` | ✅ (NAV is `null` on non-unit rows such as taxes) |
| Units | `schemes[].open` / `close` / `close_calculated`, `transactions[].units`, `transactions[].balance` | ✅ plus a balance checksum |
| Cost / average price | `schemes[].valuation.cost` | ⚠️ **holding level only**, `null` on some templates — see Gaps |
| Transaction date | `transactions[].date` (ISO `YYYY-MM-DD`) | ✅ |
| Transaction type | `transactions[].type` | ✅ 17-value enum: `PURCHASE`, `PURCHASE_SIP`, `REDEMPTION`, `SWITCH_IN(_MERGER)`, `SWITCH_OUT(_MERGER)`, `DIVIDEND_PAYOUT`, `DIVIDEND_REINVEST`, `STT_TAX`, `STAMP_DUTY_TAX`, `TDS_TAX`, `SEGREGATION`, `GIFT_IN`, `GIFT_OUT`, `REVERSAL`, `MISC`, `UNKNOWN` |
| Multi-page | Yes | v1.1.0: scheme-header parsing rewritten as anchor-delimited regions that *"stitches headers across page breaks (which the old code could not)"* — [CHANGELOG](https://github.com/codereverser/casparser/blob/main/CHANGELOG.md) |

**Also extracted (bonus for an importer):** investor name/email/mobile/address; folio `PAN`, `KYC`, `PANKYC`, per-folio holder `name` (added 1.4.0, `null` on older templates); scheme `amfi`, `type`, `nominees[]`, `advisor` (ARN/RIA), `rta_code`; transaction `description`, `amount`, `dividend_rate`, `gift_folio`; `parse_warnings[]`; CLI `gains`/`--gains-112a` capital-gains reports.

**What it fails to extract / known failure modes** (all from the repo's own README, CHANGELOG and issue tracker):

1. **Re-printed / re-saved PDFs are rejected.** *"If you 'print to PDF' an existing CAS … the watermark gets flattened from selectable text into a bitmap and the original generator metadata is wiped … casparser can no longer prove what it's looking at, and will reject the file."* — [README](https://github.com/codereverser/casparser).
2. **MFCentral statements are out of scope in v1.0.** Same README.
3. **Third-party-reformatted statements** (broker portals, Excel→PDF round-trips) are out of scope. Same README.
4. **Single-AMC statements:** not listed anywhere among supported inputs, and issue detection keys on CAS-specific watermarks (`CAMSCASWS`, `KFINCASWS`) plus a `Consolidated Account (Statement|Summary)` heading — [detect.py](https://github.com/codereverser/casparser/blob/main/casparser/parsers/detect.py). *Researcher inference (medium confidence):* a single-AMC statement of account will be classified `FileType.UNKNOWN` and rejected with `"Could not identify the CAS issuer…"`. This is **not** stated by the maintainer; it needs a fixture test (see Next steps).
5. **ISIN may come back `null`.** `schemes[].isin` is `string | null`; ISIN/AMFI/`type` enrichment depends on the bundled `casparser-isin` database, which *"is shipped with a local database which may get obsolete over time"* — [README](https://github.com/codereverser/casparser), [casparser-isin README](https://github.com/codereverser/casparser-isin).
6. **Transaction rows can degrade to `MISC`/`UNKNOWN`**, and 1.4.0 deliberately added information-only `MISC` rows (`***Registration of Nominee***`, KYC/address updates, `Transmission In`) with `amount`/`units`/`nav` = `null`. Its own release note warns: *"Parsed output for CAMS/KFintech DETAILED statements grows in this release … Pipelines that diff casparser output across versions should expect these additive changes."* — [CHANGELOG 1.4.0](https://github.com/codereverser/casparser/blob/main/CHANGELOG.md).
7. **Scheme-level data can legitimately be partial**: v1.1.0 warns when a scheme-header region is discarded without its `Opening Unit Balance` anchor — *"previously such a scheme and all its transactions vanished silently"*. Consumers must treat non-empty `parse_warnings` as "do not trust this scheme blindly" — [v1.1.0 notes](https://github.com/codereverser/casparser/releases/tag/v1.1.0).
8. **A live 1.4.x regression is open:** [#150](https://github.com/codereverser/casparser/issues/150) (opened 2026-09-10) — a CAMS detailed CAS that parsed on earlier versions now yields `ERROR: not well-formed (invalid token)`, traced by the maintainer in the issue comments to a `U+FFFE` glyph in newly-emitted MISC rows, which breaks *XML* consumers of the JSON output; a fix was promised for 1.4.2 (not released as of 2026-09-19).
9. **Open parsing bugs, several of them old and unverified-against-1.4.x:** [#88](https://github.com/codereverser/casparser/issues/88) (bonus rows where NAV is absent on some rows), [#89](https://github.com/codereverser/casparser/issues/89) (redemption annotation change, CAMS v3.4), [#90](https://github.com/codereverser/casparser/issues/90) (one scheme not parsed), [#54](https://github.com/codereverser/casparser/issues/54) (amount-only record placed in the units field), [#20](https://github.com/codereverser/casparser/issues/20) (Layout Error / scheme before folio entry), [#49](https://github.com/codereverser/casparser/issues/49) (capital gains wrong where funds merged into others), [#44](https://github.com/codereverser/casparser/issues/44) & [#109](https://github.com/codereverser/casparser/issues/109) (feature gaps in gains CSV). [#145](https://github.com/codereverser/casparser/issues/145) (folio holder name / PAN association) was fixed in 1.4.0.
10. **Password handling is on you.** `read_cas_pdf(path, password)`; wrong password raises `IncorrectPasswordError` ([detect.py](https://github.com/codereverser/casparser/blob/main/casparser/parsers/detect.py)). CAS PDFs are password-protected; commonly reported conventions are PAN uppercase (CAMS/KFin CAS) or PAN lowercase + DOB — **secondary sources only** ([Groww help](https://groww.in/help/mutual-funds/mf-track-and-switch/how-to-generate-my-consolidated-account-statement--cas--from-the-cams-website--60), [webnotes](https://v2.webnotes.in/how-to-generate-cas-cams)), so the importer must accept arbitrary passwords rather than assume a format.

**Security / CVE status:** GitHub Advisory Database query `ecosystem=pip&affects=casparser` returns **no advisories**; same query for `pypdfium2` returns none — [advisory API](https://api.github.com/advisories?ecosystem=pip&affects=casparser). Repo runs a CodeQL workflow and Dependabot. The maintainer demonstrably runs `pip-audit --strict` (in `casparser-isin`, following the bump commit: *"$ uv run --with pip-audit pip-audit --strict / No known vulnerabilities found"*) — [commit 2f12002](https://github.com/codereverser/casparser-isin/commit/2f12002e356766e20c50d65ec86de19f81a07803). *Limitation:* I could not run `pip-audit`/OSV against the exact resolved dependency set in your environment; the check above is advisory-database lookup only.

In the detailed path `cost` is **computed** from printed invested value ÷ units (rounded), which is not identical to casparser's as-printed `valuation.cost`.

**Failure modes / open issues:** the tracker shows the class of bugs you would inherit — [#25](https://github.com/BeyondIRR/cas2json/issues/25) duplicate scheme entries when the ISIN sits in the second half of the scheme block, [#22](https://github.com/BeyondIRR/cas2json/issues/22) CDSL rows whose details span multiple lines, [#17](https://github.com/BeyondIRR/cas2json/issues/17) CAMS transactions broken when the description contains `:`, [#13](https://github.com/BeyondIRR/cas2json/issues/13) missing NSDL values, and open [#16](https://github.com/BeyondIRR/cas2json/issues/16) *"[feature] Introduce a Higher-Accuracy Parsing Approach"* which states plainly that *"due to multiple variations of NSDL, CDSL statements, the parsing accuracy takes a hit. Also, schemes are not parsed correctly in either of them."* State persistence across pages exists (folio/scheme state is held outside the page loop), but there is no page-break-specific handling and no balance-reconciliation warning mechanism comparable to `parse_warnings`.

**Security / licence caveat:** its PDF engine is PyMuPDF, which is *"Dual Licensed - GNU AFFERO GPL 3.0 or Artifex Commercial License"* — [PyPI](https://pypi.org/pypi/PyMuPDF/json) — so the AGPL obligation propagates to your application if you distribute it or expose it as a network service to others. `pymupdf>=1.24.0` has no upper pin, and PyMuPDF 1.26.5–1.26.6 carries **CVE-2026-3029** (path traversal + arbitrary file write in the PyMuPDF CLI `get` helper), fixed in 1.26.7 — [OSV](https://api.osv.dev/v1/vulns/CVE-2026-3029), [GHSA-cxqh-p2w9-fmr7](https://github.com/advisories/GHSA-cxqh-p2w9-fmr7). A normal resolver will pick 1.26.7+, but this is exactly the kind of dependency you must pin (note the CVE is in the CLI helper, not the parser API — *source interpretation*).

## Privacy: does anything leave the machine?

- **casparser parse path: no.** Its dependency list contains no HTTP client, there are no `requests`/`urllib`/`httpx` imports in the dispatcher or ISIN helper, and ISIN/AMFI enrichment reads a bundled local SQLite DB (`MFISINDb` / `ISINDb`) — [PyPI JSON](https://pypi.org/pypi/casparser/json), [parsers/__init__.py](https://raw.githubusercontent.com/codereverser/casparser/main/casparser/parsers/__init__.py), [parsers/_isin.py](https://github.com/codereverser/casparser/blob/main/casparser/parsers/_isin.py). *Interpretation: high confidence, but I read the dispatcher/ISIN/detector modules only, not every file in the package.*
- **The optional `casparser-isin` CLI is the only outbound call in the family.** `--update`/`--check` fetch `https://casparser.atomcoder.com/isin.db.meta` and a ~50 MB SQLite DB (`isin.db.gz` preferred, SHA-256 verified, atomic swap) with headers `User-Agent: casparser-isin/<version>` and `X-origin-casparser: true` — [cli.py](https://github.com/codereverser/casparser-isin/blob/main/casparser_isin/cli.py). **No statement content is sent**; the transaction is a version check plus a DB download. Recommended posture for the spec: **do not run `casparser-isin --update` in the app**; ship the pinned `casparser-isin` wheel's bundled DB, and if a refresh is ever wanted, make it an explicit operator action.
- **cas2json: no network path at all** — deps are `pymupdf` + `python-dateutil` only.
- **processcaspdf: outbound AMFI NAV-file fetch on every run** (see above) — public data, but a network dependency.
- **Hosted APIs (`casparser.in`, `mfapi.in`)**: statement contents leave the machine. Excluded.

## Contradictions / disputed evidence

1. **cas2json licence labelling.** Repo `LICENSE`, SPDX headers and `pyproject.toml` all say **AGPL-3.0-or-later**; at least one search index reported "GPL-3.0-or-later" for an earlier release. Treat AGPL as authoritative ([pyproject](https://raw.githubusercontent.com/BeyondIRR/cas2json/main/pyproject.toml)).
2. **CAS PDF password convention.** Secondary sources disagree: one says PAN uppercase, another says PAN lowercase + DOB for the CAMS CAS ([Groww](https://groww.in/help/mutual-funds/mf-track-and-switch/how-to-generate-my-consolidated-account-statement--cas--from-the-cams-website--60), [webnotes](https://v2.webnotes.in/how-to-generate-cas-cams)). No official CAMS statement of the rule was reachable. **Unresolved — design for arbitrary passwords.**
3. **casparser "reprinted PDF" guard vs. real-world capture flows.** The README frames rejection as a feature ("can no longer prove what it's looking at"), while issue [#107](https://github.com/codereverser/casparser/issues/107) shows users hitting header-detection errors on legitimate-looking files. Not contradictory evidence about facts, but a reminder that issuer detection is a heuristic and version-fragile.
4. **cas2json's NSDL/CDSL support** is advertised on PyPI without the BETA caveat that the README and issue [#16](https://github.com/BeyondIRR/cas2json/issues/16) carry. Prefer the README/tracker.

## Missing evidence

- **No hands-on parse.** I could not run either library against a real CAMS CAS (no sample statement available to me). All extraction claims are from README/schema/changelog/source, not from observed output on a long multi-page statement.
- **Single-AMC statements are untested territory.** No source states that casparser or cas2json handles a single-AMC statement of account; my expectation that both fail issuer detection is *inference*.
- **Official CAMS format documentation was not readable.** The CAMS CAS pages are JavaScript-rendered and the AMFI CAS FAQ PDF (`portal.amfiindia.com/spages/FAQ on CAS.pdf`) returned metadata only, no extractable text. So SEBI/RTA-level statements of what a CAS contains are asserted here only via secondary summaries and casparser's own tables.
- **No dependency-level CVE sweep.** GitHub Advisory Database lookups for `casparser` and `pypdfium2` are empty; I did not run `pip-audit`/OSV over the fully resolved environment (so pydantic/click/rich/dateutil transitive advisories at your exact pinned versions are unverified).
- **casparser 1.4.2 status.** Issue #150's fix was promised for 1.4.2; no 1.4.2 exists as of 2026-09-19.

## Gaps by parser → import-experience error-handling requirements

These are the concrete failure modes the importer must surface as friendly, actionable errors rather than stack traces or silent data loss.

### From casparser (primary)

| # | Gap / failure mode | Required import behaviour |
|---|---|---|
| G1 | Non-original PDF (print-to-PDF, "Save as PDF", broker-reformatted, Excel→PDF) → rejected by design | Detect and say: *"This looks like a re-saved copy of your statement. Print-to-PDF strips the RTA watermark. Please download the statement fresh from CAMS/KFintech and upload that file."* Never attempt a best-effort parse. |
| G2 | MFCentral statement unsupported | Name MFCentral explicitly in the error: *"MFCentral statements aren't supported yet; request the CAMS or KFintech CAS instead."* |
| G3 | Single-AMC statement unsupported (inference) | Error must distinguish "not a CAS at all" from "corrupt/password-protected": *"This looks like a single-AMC account statement. We need the Consolidated Account Statement (CAS) covering all your folios."* |
| G4 | Wrong/missing password (`IncorrectPasswordError`) | Prompt for the password, allow retry, never echo it, and hint at both known conventions without asserting one; allow the user to correct and re-attempt without re-uploading. |
| G5 | `parse_warnings` non-empty (transaction/balance discontinuity) | Do **not** block the import, but show a per-scheme warning banner and mark affected schemes as "unverified — figures may be incomplete", with the raw statement retained for re-import. |
| G6 | `schemes[].isin` is `null` | Import anyway; key holdings by `(rta, rta_code)`/`amfi` when ISIN is absent; surface "ISIN unknown for N schemes" so pricing/enrichment gaps are visible rather than silently producing unmatched holdings. |
| G7 | `valuation.cost` is `null` | Fall back to cost derived from transactions (Σ amount for purchases, adjusted for redemptions) and **label it as derived**, not as printed. |
| G8 | No per-transaction cost basis / average price | Compute per-lot cost from `amount`/`units` at import time, and record the derivation in the data model, since the statement doesn't state it. |
| G9 | `MISC`/`UNKNOWN` transaction types, informational rows (`amount`/`units`/`nav` = `null`) | Import as informational events that do not affect units or cost; never treat `UNKNOWN` as a purchase/sale; expose a review queue for `UNKNOWN` rows. |
| G10 | Multi-registrar CAS (schemes with differing `rta` inside one CAMS-issued file) | Import per-scheme registrar, not per-file; don't assume one RTA per statement. |
| G11 | Version drift: output changes additively between minor releases (1.4.0 note), and one live 1.4.x XML-serialisation regression exists (#150) | Pin the parser version; make the import record `casparser.__version__` against each uploaded statement; strip/normalise non-XML-safe characters from descriptions before any XML/CSV export. |
| G12 | Long multi-page statements | Stream/paginate results; never assume single-page layouts; warn if the parsed folio/scheme count looks low vs. the statement's own footers/totals. |
| G13 | Old open bugs on specific transaction shapes (bonus rows without NAV #88, amount-only rows #54, redemptions #89, mergers #49) | Provide a per-transaction "something looks wrong" escape hatch and an import log of raw lines for the flagged scheme. |
| G14 | ISIN DB staleness | Do **not** auto-update (`casparser-isin --update` calls the author's server); ship a pinned DB and make refresh an explicit, off-by-default operator action. |

### From cas2json (fallback only)

| # | Gap | Required behaviour |
|---|---|---|
| C1 | NSDL/CDSL are holdings-only (no transactions) | If used, import holdings and mark history as "unavailable from this file". |
| C2 | AGPL-3.0-or-later + PyMuPDF AGPL | License/compliance gate, not a UX error: decide before adoption. |
| C3 | No test suite in the repo; accuracy self-declared BETA | Do not make it the default; use only behind a per-file fallback with a visible "parsed with fallback engine" notice. |
| C4 | Duplicate scheme rows (ISIN late in the block), multi-line rows, `:` in descriptions (issues #25/#22/#17) | Deduplicate schemes by `(folio, isin)` on import and surface duplicates as a warning rather than double-counting. |
| C5 | `cost` is derived (invested value ÷ units), not as printed | Label derived cost as derived. |
| C6 | `pymupdf>=1.24.0` unpinned; CVE-2026-3029 affects 1.26.5–1.26.6 | Pin `pymupdf>=1.26.7` if adopted. |

### From the rejected parsers (context for the spec)

- `processcaspdf`: no cost field at all; unknown-AMC/wrapped scheme names silently skipped; requires internet per run; 2 stars/2 releases → do not build on it.
- `mutualfund-stmts-etl`: abandoned 2019, JVM/Tabula dependency, self-declared alpha.
- `saransh-workflows`: one release, no issues history, GitHub URL 404s.
- Hosted `casparser.in` API: statement contents leave the machine — architecturally excluded.
